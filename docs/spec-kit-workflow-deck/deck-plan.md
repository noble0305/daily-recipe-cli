# Spec Kit 开发工作流 · Bento 演示 Deck 方案

## 目标与受众

- 受众：团队开发者、评审人、技术分享会听众（已了解本仓库，需要"理解 + 采纳"）。
- 目标：让听众看完能直接跑通工作流，知道每个命令何时调用、产出什么、为什么这样做。
- 交付格式：单文件 `.bento.html`（离线自包含、可编辑、可演示），同时保留 `deck.json`。
- 时长：约 8–12 分钟（8 张主线页，每页 45–90 秒）。

## 一句话结论

Spec Kit 把"需求 → 代码"拆成 specify → clarify → plan → tasks → implement → analyze 六步可追溯流水线，文档先行、产物入仓、AI 与人同规格协作。

## 叙事弧

1. 痛点 → 答案：为什么需要规格驱动。
2. 产物全景：工作区里到底多了什么。
3. 六步主链路：每一步何时调、产出什么（核心）。
4. 团队规约：强制项，落地保障。
5. 踩坑 FAQ：常见问题与默认行为。
6. 快速参考：速记 + 评审检查单。

## state 细节页（隐藏页，靠 link 进入，← 返回）

- flow 页的 6 个节点各对应 1 个 state 页：该命令"何时调 → 做什么 → 产出 → 本项目示例片段"。
- faq 页的 4 个问题各对应 1 个 state 页：问题 + 答案 + 遵循的具体规则。
- 每个 state 页都含一个全屏透明"点击返回"热区（link 回父页）。

## 素材映射

- 数字：10 命令、6 主链路、8 提交、5 条规约 → countUp。
- 对比（痛点 vs 答案、目录 vs 细节）→ 双栏 + 表格。
- 流程（六步主链路）→ path + dash-march + 节点矩形。
- 钻取（命令细节、FAQ 答案）→ stateOf 隐藏页 + link。
- 表格：工作区结构、命令全景、提交历史、评审检查单。

## 视觉方向

- 1280×720；左右各 96px 边距（最右 x ≤ 1184）。
- 一套主色：深底 `#101418` + 象牙白 `#F2F0EA` + 单 accent `#FF9E8A`（珊瑚橙，官方主题风格）。
- 一种中文字体栈：`system-ui, -apple-system, 'PingFang SC', sans-serif`。
- 封面与目录页保留 ambient 动效；流程页 dash-march；不做装饰性箭头堆叠。
- 不引入图片/图标/emoji 作正式视觉——纯排版 + 色块 + 动效。
