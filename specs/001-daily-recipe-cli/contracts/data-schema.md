# Data Contract: recipes.json & history.json

**Date**: 2026-08-15 | **Phase**: 1 | **数据模型**: [data-model.md](../data-model.md)

本文件定义两个用户数据文件的精确格式。所有命令在读入时必须校验，非法数据抛出含字段定位的中文错误，禁止静默容错或覆盖。

## 文件位置

- 默认目录：`~/.daily-recipe-cli/`
- 覆写环境变量：`RECIPE_CLI_DIR`（存在则使用其值作为数据目录）

## `recipes.json`

顶层必须是 JSON 数组。元素：

```json
{
  "name": "番茄牛腩",
  "ingredients": ["牛腩", "番茄", "洋葱", "土豆"],
  "tags": ["荤", "费时"],
  "note": "牛腩焯水后与番茄同炖 1 小时，第二天复热更入味"
}
```

校验规则：

| 规则 | 失败时错误信息（中文） |
|------|------------------------|
| 顶层是数组 | 食谱库格式错误：顶层应为数组 |
| `name` 为非空字符串，≤30 字符 | 食谱库格式错误：第 N 条缺少有效的「菜名」 |
| `name` 不重复（大小写不敏感） | 食谱库格式错误：菜名「X」重复出现 |
| `ingredients` 为非空字符串数组 | 食谱库格式错误：第 N 条（X）的「主要食材」无效 |
| `tags` 为非空字符串数组 | 食谱库格式错误：第 N 条（X）的「标签」无效 |
| `note` 为字符串（可省略） | 食谱库格式错误：第 N 条（X）的「做法」无效 |

## `history.json`

顶层必须是 JSON 数组。元素：

```json
{
  "date": "2026-08-15",
  "recipe": "番茄牛腩",
  "source": "today"
}
```

校验规则：

| 规则 | 失败时错误信息（中文） |
|------|------------------------|
| 顶层是数组 | 历史记录格式错误：顶层应为数组 |
| `date` 为 `YYYY-MM-DD` 合法日期 | 历史记录格式错误：第 N 条日期「X」无效 |
| `recipe` 为非空字符串 | 历史记录格式错误：第 N 条缺少菜名 |
| `source` 为 `today` 或 `week` | 历史记录格式错误：第 N 条来源「X」无效 |
| `date` 不重复 | 历史记录格式错误：日期「X」重复出现 |

## 写入语义

- 原子写入：先写 `<file>.tmp`，成功后 `os.replace()` 替换原文件。
- 每次命令成功修改数据后立即落盘；读取时内存态与磁盘一致。
- 排序约定：读取后按 `date` 升序处理；写入保留自然顺序即可（读取端负责排序）。

## 示例：完整 `recipes.json`

```json
[
  {
    "name": "番茄牛腩",
    "ingredients": ["牛腩", "番茄", "洋葱", "土豆"],
    "tags": ["荤", "费时"],
    "note": "牛腩焯水后与番茄同炖 1 小时，第二天复热更入味"
  },
  {
    "name": "日式咖喱鸡",
    "ingredients": ["鸡腿肉", "土豆", "胡萝卜", "咖喱块"],
    "tags": ["荤", "快手"],
    "note": "全部切块下锅炖 20 分钟"
  }
]
```

## 示例：完整 `history.json`

```json
[
  { "date": "2026-08-14", "recipe": "日式咖喱鸡", "source": "today" },
  { "date": "2026-08-15", "recipe": "番茄牛腩", "source": "today" }
]
```
