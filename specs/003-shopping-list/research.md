# Research: shopping-list

**日期**: 2026-08-15 | **阶段**: 0 | **规格**: [spec.md](./spec.md) | **计划**: [plan.md](./plan.md)

## 结论摘要

所有技术未知项已在 plan 阶段确定，无遗留 NEEDS CLARIFICATION。本文件记录关键设计决策、权衡与被否方案，作为后续实现与复盘依据。

## 关键决策与权衡

### 1. 纯计算视图，不引入新数据文件

- **选择**：购物清单由核心聚合函数对既有 `recipes.json` / `history.json` 实时计算，每次命令/请求时重新聚合，不落盘。
- **理由**：① 数据源单一——清单永远与当前数据一致，无需同步；② 零迁移成本——不破坏既有数据契约；③ 数据量级极小（窗口 ≤ 数十道菜），每次重算开销可忽略。
- **被否方案**：生成清单后缓存到 `shopping.json`——带来缓存失效、过期数据、双份维护成本，收益仅是对重算无感知的秒级性能，不成比例。

### 2. 窗口语义：未来 `--days` 天（含今日），默认 7

- **选择**：`shopping-list` 聚合 `[今天, 今天 + days - 1]` 闭区间内的历史记录；`--today` 等价 `--days 1`。
- **理由**：① 未来 7 天自然覆盖「周中补货（今天明天）+ 周末囤菜（本周 week 计划）」两个场景；② 语义简单直观，与去重窗口（`--days`）参数名一致，降低认知负担。
- **被否方案**：只聚合今日——无法覆盖周末囤菜；需要用户手动传菜名——丢失自动化价值（规格已确认选「未来 7 天」）。

### 3. 食材去重：精确字符串匹配，不做同义归一

- **选择**：以食谱 `ingredients` 原始字符串为键做去重合并；「番茄/西红柿」这类同义项视为不同食材。
- **理由**：① 语义归一需要维护同义词表，违背宪法原则 I（YAGNI）且引入运行时依赖风险；② 带饭清单场景中用户通常自己知道「番茄=西红柿」，做归一收益低。
- **被否方案**：同义词归一（如基于常见食材表）——复杂化、易误判、收益低。

### 4. 排序：按食材名字符串排序（UTF-8 字节序）

- **选择**：清单条目按食材名排序输出，CLI 与页面共用服务端（聚合函数）的排序结果。
- **理由**：确定性排序保证 CLI 与页面输出一致（规格 SC-004）；中文按 UTF-8 字节序在多数场景下近似拼音序，够用。
- **被否方案**：拼音/笔画排序——需引入额外数据（拼音映射），收益低。

### 5. 跳过语义：单菜异常不中断整体

- **选择**：某道已安排菜不在食谱库（已被删除）或其 `ingredients` 缺失/非法时，跳过该菜并记入 `skippedRecipes`，其余菜正常聚合。
- **理由**：历史存菜名快照，删除食谱不影响历史（001 契约），因此「有安排但无食材」是常态而非异常；整体中断会让清单不可用。
- **权衡**：与 001 的「非法数据抛 `DataError`」不冲突——`storage.load_recipes()` 仍会拒绝结构非法的**整个** `recipes.json`；此处的跳过仅针对「单条菜不在库/食材缺失」这一业务性缺失，属规格明确的行为。

### 6. `--no-merge` 的语义：来源并列

- **选择**：`--no-merge` 关闭去重合并——同一食材每出现于一道菜就单独列一条（`sources` 仅含该菜）。
- **理由**：保留「精细核对」选项，让用户能按菜逐项确认每样食材该买几份（如两道菜都要番茄时自己决定买几个）。
- **被否方案**：不做该参数——默认合并已够用，但丢失按菜核对的能力；直接跳过多余。

### 7. 页面集成：新增只读端点，复用同一聚合函数

- **选择**：`GET /api/shopping-list`（只读，无写锁）转调 `shopping.build_list`；页面「购物清单」区域 fetch 渲染。
- **理由**：与 002 的「页面 = 渲染层、核心逻辑复用、行为一致」原则一致；只读端点无需处理写并发。
- **被否方案**：页面单独实现聚合——双份逻辑必然漂移，违背 SC-004。

## 数据文件

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 菜名不在食谱库导致聚合失败 | 单菜跳过 + `skippedRecipes` 提示，不中断整体（规格边界情况已覆盖） |
| 窗口语义被误读（是否含今日） | 规格 Assumptions 明确「未来 `--days` 天含今日」；`--today` 为轻量替代 |
| 页面与 CLI 输出漂移 | 共用 `shopping.build_list` 单一实现 + 契约测试覆盖（spec SC-004） |
| 食材同义导致清单不完美 | 明确不做语义归一（决策 3），文档中说明；用户可在 `recipes.json` 手改统一食材命名 |
